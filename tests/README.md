# Tests

Тесты Finpipe разделены по уровню проверки и степени зависимости от внешних систем.

## Structure

### unit

Быстрые изолированные тесты.

Не используют сеть, файловую систему или реальные внешние сервисы.

Проверяют:

- бизнес-логику;
- генерацию документов;
- ORM-модели;
- Telegram handlers;
- Gmail сервисы;
- валидацию данных.

Примеры:

- генерация Invoice;
- генерация Transfer Request;
- импорт профиля;
- работа с подписями;
- логика Telegram-бота.

---

### integration

Проверяют взаимодействие нескольких компонентов системы.

Допустимо использование:

- локальной SQLite базы;
- файловой системы;
- шаблонов документов;
- нескольких сервисов одновременно.

Примеры:

- импорт профиля в базу данных;
- генерация документа целиком;
- работа ORM поверх SQLite;
- Telegram workflow;
- конвертация DOCX → PDF.

---

### external

Тесты с реальными внешними интеграциями.

Примеры:

- Telegram API;
- Gmail API;
- OAuth сценарии.

По умолчанию не запускаются в CI.

Используются для ручной проверки интеграций.

---

### fixtures

Общие pytest fixtures.

Размещаются здесь только если используются несколькими тестовыми модулями.

Если фикстура нужна одному тесту или одному файлу — оставлять рядом с тестом.

---

### fakes

Тестовые реализации внешних зависимостей.

Предпочтительный способ изоляции тестов.

Примеры:

- FakeTelegram
- FakeGmail
- FakeStorage

---

### resources

Тестовые артефакты:

- PDF шаблоны;
- DOCX шаблоны;
- изображения;
- примеры документов.

---

## Test Philosophy

Основные принципы проекта:

- unit-тесты должны быть быстрыми;
- тесты должны быть независимыми друг от друга;
- предпочтительны Fake-объекты вместо Mock-объектов;
- один тест должен проверять одно поведение;
- тест должен быть понятен без чтения реализации;
- перед добавлением нового теста проверить, не покрыт ли сценарий уже существующим тестом.

---

## Naming

Использовать формат:

```text
test_<feature>.py
```

Примеры:

```text
test_unit_invoice_generator.py
test_unit_storage_user_config.py
test_integration_profile_template_import.py
test_external_telegram.py
```

Название должно описывать проверяемое поведение, а не внутреннюю реализацию.

---

## Running Tests

Запустить все тесты:

```bash
pytest
```

Только unit:

```bash
pytest tests/unit
```

Только integration:

```bash
pytest tests/integration
```

Только external:

```bash
pytest tests/external
```

---

## CI

В CI должны запускаться только быстрые и детерминированные тесты.

Внешние интеграции не должны быть обязательными для прохождения пайплайна.

Перед открытием Pull Request рекомендуется запускать:

```bash
pytest
```

и убеждаться, что все тесты проходят локально.
