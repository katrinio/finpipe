# Tests

Тесты разделены по уровню проверки.

## Structure

### unit

Быстрые изолированные тесты без внешних зависимостей.

Проверяют отдельные функции, классы и небольшие компоненты.

Примеры:

- генерация инвойса;
- парсинг банковского PDF;
- построение email;
- работа с ORM-моделями;
- логика Telegram-бота.

### integration

Проверяют взаимодействие нескольких компонентов системы.

Примеры:

- генерация полного документа;
- конвертация DOCX → PDF;
- обработка банковского запроса;
- работа с локальной базой данных.

### external

Тесты, требующие доступа к внешним сервисам.

Примеры:

- Telegram API;
- Gmail API;
- другие реальные интеграции.

По умолчанию не должны запускаться в CI без необходимости.

### fixtures

Общие pytest fixtures.

Используются только для повторно используемых объектов и настроек.

Если фикстура нужна одному тесту, лучше оставить её рядом с тестом.

### resources

Тестовые файлы:

- PDF-шаблоны;
- DOCX-шаблоны;
- изображения;
- прочие тестовые артефакты.

## Rules

- Unit-тесты должны быть быстрыми и независимыми.
- Не создавать фикстуру ради одного теста.
- Предпочитать Fake-объекты Mock-объектам.
- Новые тесты размещать рядом с тестируемым доменом.
- Перед добавлением нового теста проверить, не покрывает ли сценарий уже существующий тест.

## Naming

Использовать формат:

test_<feature>.py

Примеры:

- test_pdf_signer.py
- test_generate_invoice.py
- test_telegram_bot.py

Название должно описывать тестируемое поведение, а не внутреннюю реализацию.
