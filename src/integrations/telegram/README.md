# 🤖 Telegram Integration

Telegram — основной пользовательский интерфейс Finpipe.

Через Telegram пользователь управляет профилем, подписью, Gmail-интеграцией и генерацией документов.
Владелец управляет onboarding и доступом пользователей.

---

## 🏗️ Архитектура

```
Telegram Update
      │
      ▼
  TelegramBot          ← получение updates, проверка доступа, состояния
      │
      ▼
  CommandRouter        ← маршрутизация команд, аудит
      │
      ▼
  Domain Handler       ← Telegram-специфичная логика
      │
      ▼
  Service              ← бизнес-логика
      │
      ▼
  Storage              ← PostgreSQL
```

---

## 📁 Структура файлов

### `bot.py`

Точка входа. Получает updates, регистрирует пользователей, проверяет доступ, управляет состояниями, делегирует в `CommandRouter`.

### `commands.py`

Константы пользовательских команд (`/start`, `/menu` и др.).

### `states.py`

Список состояний Telegram workflow:

| Состояние | Когда используется |
|---|---|
| `WAITING_SIGNATURE_UPLOAD` | Ожидание файла подписи |
| `WAITING_PROFILE_UPLOAD` | Ожидание файла профиля |
| `WAITING_INVOICE_AMOUNT` | Ожидание суммы Invoice |
| `WAITING_ADD_USER` | Ожидание telegram_id нового пользователя |
| `WAITING_CONFIRM_ADD_USER` | Ожидание подтверждения выдачи доступа |
| `WAITING_REMOVE_USER` | Ожидание telegram_id для отзыва доступа |

### `state_service.py`

Установка, чтение и очистка состояний пользователя.

## 🧩 Handlers

| Handler | Назначение |
|---|---|
| `command_router.py` | Центральная маршрутизация всех команд |
| `menu_handlers.py` | Навигация по меню |
| `profile_handlers.py` | Загрузка шаблона, импорт профиля, просмотр |
| `signature_handlers.py` | Загрузка и удаление подписи |
| `gmail_handlers.py` | Подключение, отключение, статус, сброс истории |
| `document_handlers.py` | Salary Invoice, Conversion Order, Bank Confirmation |
| `owner_handler.py` | Управление пользователями (только для owner) |
| `system_handlers.py` | Status, healthcheck, about, whoami |
| `state_handlers.py` | Обработка файлов в upload-состояниях |

---

## 👥 Роли

| Роль | Доступ |
|---|---|
| **Guest** | `About`, `Who Am I` — только просмотр |
| **User** | Профиль, подпись, документы, Gmail |
| **Owner** | Всё выше + административные команды |

После первого взаимодействия пользователь становится `KnownUser`, но доступ не получает — его выдаёт Owner.

---

## 🔓 Выдача доступа

```
Пользователь пишет боту → регистрируется в KnownUser
                                      │
Owner: 🛠️ Админка → 👥 Пользователи → ➕ Добавить
                                      │
                            вводит telegram_id
                                      │
                          подтверждает найденного пользователя
                                      │
                              AllowedUser создаётся
```

Если пользователь ещё не открывал бота — доступ выдать нельзя.

├── 👤 Профиль
│   ├── 👤 Мой профиль
│   ├── 📥 Шаблон профиля

│   │   │   └── → предложение отправить компании

│

│   └── 📧 Gmail

│       ├── ❌ Отключить

│       └── 🗑 Сбросить историю писем

    ├── About
    └── Who Am I

Для Owner дополнительно:

```
🛠️ Админка
└── 👥 Пользователи
    ├── ➕ Добавить пользователя
    ├── ➖ Удалить пользователя
    └── 📋 Список пользователей
```

## ➕ Добавить новую команду

1. Добавить кнопку в `ui/buttons/`
2. Добавить пункт меню при необходимости
3. Реализовать метод в соответствующем handler
4. Зарегистрировать в `CommandRouter._build_command_handlers()`
5. Добавить unit-тест

---

## ➕ Добавить новый upload-flow

1. Добавить значение в `UserState`
2. Зарегистрировать обработчик в `TelegramBot._state_handlers`
3. Реализовать обработчик файла
4. Добавить команду перехода в состояние

Unit-тесты для нового flow:

- установка состояния
- успешная загрузка
- невалидный файл
- отмена через команду
