# Telegram Integration

Telegram является основным пользовательским интерфейсом Finpipe.

Через Telegram пользователь управляет профилем, подписью, Gmail-интеграцией и генерацией документов.

Отдельно через Telegram владелец управляет onboarding и доступом пользователей.

---

# Architecture

text Telegram Update     ↓ TelegramBot     ↓ CommandRouter     ↓ Domain Handler     ↓ Service     ↓ Storage 

Ответственность слоёв:

text TelegramBot     Получение и обработка Telegram updates  CommandRouter     Маршрутизация команд  Handlers     Telegram-специфичная логика  Services     Бизнес-логика  Storage     Долговременное хранение данных 

---

# File Responsibilities

## bot.py

Точка входа Telegram-интеграции.

Отвечает за:

- получение updates;
- регистрацию известных пользователей;
- проверку доступа;
- обработку пользовательских состояний;
- делегирование команд в CommandRouter.

---

## commands.py

Константы пользовательских команд и системных сообщений.

---

## states.py

Список пользовательских состояний Telegram workflow.

Примеры:

- ожидание подписи;
- ожидание профиля;
- ожидание суммы Invoice.
- ожидание telegram_id нового пользователя;
- ожидание подтверждения выдачи доступа;
- ожидание telegram_id для отзыва доступа.

---

## state_service.py

Работа с пользовательскими состояниями.

Позволяет:

- установить состояние;
- получить состояние;
- очистить состояние.

---

## ui/

Описание интерфейса Telegram.

Содержит:

- кнопки;
- меню;
- пользовательские сообщения.

---

## handlers/

Telegram handlers, сгруппированные по доменам.

### command_router.py

Центральная маршрутизация Telegram-команд.

---

### menu_handlers.py

Навигация и отображение меню.

---

### profile_handlers.py

Работа с профилем пользователя.

- загрузка шаблона;
- импорт профиля;
- просмотр профиля.

---

### signature_handlers.py

Работа с подписью пользователя.

- загрузка;
- удаление;
- проверка статуса.

---

### gmail_handlers.py

Управление Gmail-интеграцией.

- подключение;
- отключение;
- статус подключения.

---

### document_handlers.py

Генерация документов.

- Salary Invoice;
- Conversion Order;
- Bank Confirmation.

---

### owner_handler.py

Команды владельца системы.

- управление пользователями;
- административные действия.
- безопасная выдача доступа только известным пользователям.

---

### system_handlers.py

Системные команды.

- status;
- healthcheck;
- about;
- whoami.

---

### state_handlers.py

# Roles

## Guest

Неавторизованный пользователь.

Доступны только:

- About
- Who Am I

После первого взаимодействия Guest попадает в KnownUser, но не получает доступ автоматически.

---

## User

Авторизованный пользователь.

Доступны:

- профиль;
- подпись;
- документы;
- Gmail.

---

## Owner

Владелец системы.

Дополнительно доступны административные команды.

---

# Access Flow

Выдача доступа построена в два шага.

## 1. Пользователь открывает бота

После любого входящего update Telegram-пользователь регистрируется в KnownUser.

Система запоминает:

- telegram_id
- username
- first_name
- last_seen_at

## 2. Владелец выдаёт доступ

Поток:

- `🛠️ Админка`
- `👥 Пользователи`
- `➕ Добавить пользователя`
- ввод `telegram_id`
- подтверждение найденного пользователя

Если пользователь ещё не открывал бота, доступ не выдаётся.

AllowedUser остаётся единственным источником прав доступа.

# How to Add a New Command

1. Добавить кнопку в ui/buttons.py.
2. Добавить пункт меню при необходимости.
3. Реализовать метод в соответствующем handler.
4. Зарегистрировать команду в CommandRouter.
5. Добавить unit-тест.
6. Добавить integration-тест при необходимости.

---

# How to Add a New Upload Flow

1. Добавить новое значение в UserState.
2. Зарегистрировать обработчик в TelegramBot._state_handlers.
3. Реализовать обработчик файла.
4. Добавить команду перехода в состояние.
5. Добавить unit-тесты:

   - установка состояния;
   - успешная загрузка;
   - невалидный файл;
   - отмена через команду.

# Testing

Для каждой новой Telegram-функции рекомендуется добавить:

- unit-тест handler;
- тест маршрутизации команды;
- тест пользовательского workflow;
- integration-тест при необходимости.

Основная директория тестов:

```text
tests/unit/telegram
tests/integration/telegram
``
