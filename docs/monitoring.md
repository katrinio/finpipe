Monitoring

Finpipe поддерживает базовый мониторинг через отдельный Telegram-чат.

Как это работает

При возникновении системных событий приложение пишет запись в EventLogger. После сохранения события зарегистрированный monitoring handler отправляет уведомление в Telegram.

Уведомления содержат:

* тип события (event_type);
* уровень важности (severity);
* дополнительные детали (details), если они указаны.

Куда отправляются уведомления

Приоритет выбора чата:

1. MONITORING_CHAT_ID
2. BOT_OWNER_TELEGRAM_ID (fallback)

Это позволяет использовать отдельный закрытый чат для мониторинга и не смешивать системные уведомления с пользовательским взаимодействием с ботом.

Архитектура

Компоненты мониторинга:

* src/services/monitoring/notifications.py — доставка уведомлений в Telegram;
* EventLogger — регистрация и публикация событий;
* register_monitoring_notifications() — подключение monitoring handler;
* src/integrations/telegram/bot.py — регистрация мониторинга при старте приложения.

Изоляция мониторингового чата

Мониторинговый чат не является отдельным интерфейсом управления ботом.

Его назначение — получение автоматических системных уведомлений.

Для предотвращения конфликтов между пользовательскими и системными сценариями сообщения из мониторингового чата исключены из обычного пользовательского роутинга. Благодаря этому сообщения и команды в мониторинговом чате не приводят к ответам вида «Неизвестная команда» в личном чате владельца.

Ограничения MVP

Текущая реализация предоставляет только доставку уведомлений.

Поддержка интерактивных команд мониторинга, управления системой и диагностики через мониторинговый чат пока не реализована.
## Monitoring

Monitoring в Finpipe вынесен в отдельный закрытый Telegram-чат.

### Назначение

- системные события;
- краткая диагностика;
- изоляция monitoring-сценариев от пользовательского интерфейса бота.

### Источник событий

- `EventLogger` пишет события в `app_events`;
- после записи событие пробрасывается в Telegram через `register_monitoring_notifications()`;
- сообщение отправляется в `MONITORING_CHAT_ID`;
- если `MONITORING_CHAT_ID` не задан, используется `BOT_OWNER_TELEGRAM_ID`.

### Формат уведомления

- тип события;
- уровень severity;
- `details`, если они есть.

### Monitoring-команды

Команды обрабатываются только в monitoring chat:

- `/status` — краткий статус приложения;
- `/health` — базовая проверка зависимостей;
- `/events` — последние системные события;
- `/errors` — последние ошибки;
- `/chatid` — id текущего чата.

### Поведение

- сообщения из monitoring chat не попадают в пользовательский router;
- обычный пользовательский чат не получает ответы на monitoring-команды;
- неизвестный текст в monitoring chat игнорируется безопасно;
- side effects в пользовательских состояниях не создаются.

### Граница потоков

- основной чат бота остаётся только для пользовательских сценариев Finpipe;
- monitoring chat остаётся только для системных уведомлений и диагностики;
- кнопки monitoring из пользовательского меню убраны, команды доступны текстом.
