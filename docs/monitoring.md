📡 Monitoring

Finpipe поддерживает встроенный мониторинг через отдельный Telegram-чат.

Мониторинг позволяет получать системные уведомления, просматривать состояние приложения и выполнять базовую диагностику без доступа к VPS.

🎯 Назначение

Monitoring chat используется для:

* системных событий;
* уведомлений об ошибках;
* диагностики состояния приложения;
* просмотра последних событий системы.

Пользовательские сценарии и мониторинг полностью разделены.

⸻

⚙️ Как это работает

Все системные события проходят через EventLogger.

При возникновении события:

1. EventLogger сохраняет запись в таблицу app_events;
2. зарегистрированные monitoring handlers получают событие;
3. событие отправляется в Telegram monitoring chat.

Таким образом таблица app_events является единым журналом событий системы.

⸻

📨 Куда отправляются уведомления

Приоритет выбора чата:

1. MONITORING_CHAT_ID
2. BOT_OWNER_TELEGRAM_ID (fallback)

Если отдельный monitoring chat не настроен, уведомления будут приходить владельцу бота.

⸻

📝 Формат уведомлений

Уведомления содержат:

* тип события (event_type);
* уровень важности (severity);
* дополнительные детали (details), если они указаны.

Пример:

⚠️ document_generation_failed
Severity: error
Invoice template not found

⸻

🏗 Архитектура

Основные компоненты мониторинга:

* EventLogger — регистрация системных событий;
* app_events — журнал событий;
* register_monitoring_notifications() — подписка на события мониторинга;
* src/services/monitoring/notifications.py — доставка уведомлений в Telegram;
* src/integrations/telegram/bot.py — регистрация мониторинга при старте приложения.

⸻

🛠 Monitoring-команды

Команды обрабатываются только в monitoring chat.

/status

Краткий статус приложения.

/health

Проверка основных зависимостей и готовности системы.

/events

Последние системные события из app_events.

/errors

Последние ошибки приложения.

/chatid

Показывает идентификатор текущего Telegram-чата.

⸻

🔒 Изоляция monitoring chat

Monitoring chat не является пользовательским интерфейсом Finpipe.

Для предотвращения конфликтов:

* сообщения из monitoring chat не попадают в обычный пользовательский router;
* пользовательские состояния не обрабатываются;
* monitoring-команды не работают в пользовательских чатах;
* неизвестные сообщения безопасно игнорируются;
* действия мониторинга не влияют на пользовательские сценарии.

⸻

🔀 Разделение потоков

Пользовательский чат

Используется только для работы с Finpipe:

* генерация документов;
* OAuth-подключения;
* управление профилем;
* пользовательские сценарии.

Monitoring chat

Используется только для:

* системных уведомлений;
* диагностики;
* просмотра состояния приложения;
* административных monitoring-команд.

Кнопки мониторинга в пользовательском интерфейсе отсутствуют — все monitoring-функции доступны через текстовые команды.

⸻

🚧 Текущие ограничения

Monitoring ориентирован на эксплуатацию одного экземпляра приложения на одном VPS.

В текущей реализации отсутствуют:

* внешние системы мониторинга (Grafana, Prometheus);
* централизованный сбор логов;
* распределённый трейсинг;
* автоматическая агрегация и дедупликация ошибок.

При необходимости эти возможности могут быть добавлены поверх существующей системы событий.
