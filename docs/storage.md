# Storage

Storage отвечает за долговременное хранение данных Finpipe.

Все пользовательские настройки, профили, состояния Telegram и данные интеграций сохраняются в базе данных, выбранной через `DATABASE_URL`, и переживают перезапуск приложения.

---

# Database Location

Finpipe uses PostgreSQL.

Example:

`DATABASE_URL=postgresql+psycopg://user:password@localhost:5432/finpipe`

---

# Data Categories

В системе хранятся два типа данных.

## User Data

Данные, принадлежащие конкретному пользователю:

- профиль работодателя;
- банковские реквизиты;
- настройки Invoice;
- электронная подпись;
- Gmail аккаунт.
- данные о Telegram-пользователе, уже открывавшем бота.

---

## System Data

Служебные данные приложения:

- разрешённые пользователи;
- известные пользователи Telegram;
- audit log;
- Telegram states;
- OAuth sessions;
- история операций и попыток генерации документов;
- обработанные сообщения;
- обработанные Telegram updates.

---

# Data Lifetime

Следующие данные переживают перезапуск приложения:

- профили пользователей;
- банковские реквизиты;
- Gmail аккаунты;
- подписи;
- настройки Invoice;
- состояния Telegram workflow;
- OAuth sessions;
- audit log;
- история операций и история генерации документов;
- список известных пользователей Telegram;
- список авторизованных пользователей.

---

# Document Generation History

История генерации документов хранится в таблице `document_generation_history`.

Она используется как журнал попыток, а не как признак того, что документ уже существует.

Для каждой попытки сохраняются:

- `document_type`
- `document_number`
- `telegram_id`
- `status`
- `error_message`
- `created_at`

Поддерживаемые типы документов:

- `salary_invoice`
- `bank_confirmation`
- `conversion_order`

Повторная генерация одного и того же документа разрешена.

Сгенерированные PDF и DOCX не используются как долговременное хранилище истории. История хранится в БД.

# Access Model

Finpipe использует две отдельные сущности для Telegram-доступа.

## KnownUser

Известный Telegram-пользователь.

Появляется после первого взаимодействия с ботом.

Хранит:

- telegram_id
- username
- first_name
- created_at
- last_seen_at

Не даёт прав доступа.

## AllowedUser

Пользователь, которому выдан доступ к Finpipe.

Хранит:

- telegram_id
- username
- роль пользователя
- created_at

Используется для проверки прав доступа и ролей.

# Security

Finpipe хранит чувствительные пользовательские данные.

Дополнительно защищаются:

## Signature

Подписи пользователей хранятся в зашифрованном виде.

---

## Gmail OAuth

Refresh token Gmail хранится в зашифрованном виде.

---

## Logging

Чувствительные данные не должны попадать в логи приложения.

В частности:

- IBAN;
- номер счёта;
- email;
- адрес;
- содержимое профиля;
- OAuth токены;
- содержимое документов.

---

# Timestamp Format

Все временные метки ORM-хранилища сохраняются в формате:

`YYYY-MM-DD HH:MM:SS`

без микросекунд.

Для стандартных служебных временных меток используется `CURRENT_TIMESTAMP`.

Если время задаётся из Python, оно нормализуется до секунд перед сохранением.

---

# Backup

Для создания резервной копии используйте средства PostgreSQL, например `pg_dump`.

---

# Recovery

Для восстановления используйте `pg_restore` или штатный механизм PostgreSQL.

После восстановления достаточно перезапустить приложение.

---

# Migration Notes

Схема создаётся и обновляется через Alembic миграции.

При запуске приложения миграции применяются автоматически.

При добавлении новой ORM-модели рекомендуется:

1. Добавить модель в src/storage/orm/.
2. Добавить тесты.
3. Обновить документацию, если изменилась структура хранения данных.

---

# Troubleshooting

## Потеря данных после перезапуска

Проверить:

- корректно ли задан `DATABASE_URL`;
- не была ли удалена база данных вручную.

---

## Ошибки после обновления приложения

Проверить:

- структура ORM соответствует текущему коду;
- база данных создана актуальной версией приложения.

При необходимости выполнить резервное копирование и пересоздать базу данных.
