# FINPIPE 🚧 In Progress 🚧

Finpipe — сервис для автоматизации работы с инвойсами, банковскими PDF и Gmail через Telegram.

Проект начинался как набор локальных скриптов для подготовки документов, а постепенно вырос в единый сервис с Telegram-ботом, SQLite-хранилищем, пользовательскими профилями и интеграциями с Gmail.

---

## Что умеет Finpipe

### 📄 Документы

- Генерация Invoice.
- Генерация Transfer Request.
- Подготовка банковских PDF.
- Автоматическая подстановка пользовательских данных.
- Вставка электронной подписи в документы.

### 📧 Gmail

- Подключение пользовательского Gmail-аккаунта.
- Поиск банковских писем.
- Скачивание PDF-вложений.
- Отправка писем через Gmail API.

### 🤖 Telegram

Telegram-бот является основным пользовательским интерфейсом системы.

Через Telegram доступны:

- управление профилем;
- загрузка подписи;
- настройка параметров Invoice;
- генерация документов;
- управление Gmail-интеграцией;
- просмотр состояния профиля и системы.

Подробное описание интерфейса находится в:

```text
src/integrations/telegram/README.md
```

## Onboarding и доступ

Доступ в Finpipe выдаётся только пользователям, которые уже взаимодействовали с ботом.

Поток выглядит так:

1. Пользователь открывает бота и нажимает `/start`.
2. Бот сохраняет пользователя во внутреннем реестре известных пользователей.
3. Владелец открывает:
   - `🛠️ Админка`
   - `👥 Пользователи`
   - `➕ Добавить пользователя`
4. Вводит `telegram_id`.
5. Если пользователь уже открывал бота, система показывает найденного пользователя и просит подтверждение.
6. После подтверждения пользователю выдаётся доступ.

Если пользователь ещё не открывал бота, доступ выдан не будет.

## Пользователи и доступ

Finpipe использует две отдельные модели:

### KnownUser

Известный Telegram-пользователь.

Означает только то, что пользователь уже писал боту.

Не даёт прав доступа.

Хранит:

- telegram_id
- username
- first_name
- created_at
- last_seen_at

### AllowedUser

Пользователь, которому уже выдан доступ.

Является единственным источником прав доступа.

Хранит:

- telegram_id
- username
- роль пользователя
- дату создания

## Роли

Finpipe поддерживает несколько ролей.

### Guest

Неавторизованный пользователь.

Доступны только:

- информация о проекте;
- команда Who Am I.

### User

Авторизованный пользователь.

Доступны:

- профиль;
- документы;
- Gmail-интеграция;
- работа с подписью.

### Owner

Владелец сервиса.

Дополнительно доступно:

- управление пользователями;
- административные функции.

---

## Административные действия

Владелец может:

- выдать доступ известному пользователю;
- отозвать доступ;
- посмотреть список пользователей с доступом.

При отзыве доступа запись KnownUser сохраняется.

- payment_number
- payment_code
- payment_description

### 💰 Настройки Invoice

- invoice_amount

После импорта данные сохраняются в базе данных и используются всеми документами системы.

## Безопасность

- Gmail refresh token хранится в зашифрованном виде.
- Электронная подпись хранится в зашифрованном виде.
- Пользовательские данные вынесены из ENV в SQLite.
- Все действия пользователей записываются в audit log.
- Чувствительные данные не должны попадать в логи приложения.

```text

    ↓

    ↓

    ↓
```

Используется SQLite.

- профили;
- банковские реквизиты;
- настройки Invoice;
- подписи;
- Gmail-аккаунты;
- audit log;
- системные состояния.

Данные переживают перезапуск приложения.

Каталог базы данных создаётся автоматически при старте.


## Локальный запуск

### 1. Создать виртуальное окружение

```bash
python -m venv .venv
source .venv/bin/activate
```

### 2. Установить Poetry

```bash
pip install poetry==2.2.1
```

### 3. Установить зависимости

```bash
poetry install --no-interaction --no-ansi --no-cache
```

### 4. Установить git hooks

```bash
poetry run pre-commit install
```
