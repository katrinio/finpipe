# FINPIPE 🚧 In Progress 🚧

Finpipe — сервис для автоматизации работы с инвойсами, банковскими PDF и Gmail через Telegram.

Проект начинался как набор локальных скриптов для подготовки документов, а постепенно вырос в единый сервис с Telegram-ботом, SQLite-хранилищем, пользовательскими профилями и интеграциями с Gmail.

---

## Что умеет Finpipe

### 📄 Документы

- Генерация Invoice.
- Генерация Transfer Request.
- Подготовка банковских PDF.
- Автоматическая подстановка пользовательских данных.
- Вставка электронной подписи в документы.

### 📧 Gmail

- Подключение пользовательского Gmail-аккаунта.
- Поиск банковских писем.
- Скачивание PDF-вложений.
- Отправка писем через Gmail API.

### 🤖 Telegram

Telegram-бот является основным пользовательским интерфейсом системы.

Через Telegram доступны:

- управление профилем;
- загрузка подписи;
- настройка параметров Invoice;
- генерация документов;
- управление Gmail-интеграцией;
- просмотр состояния профиля и системы.

Подробное описание интерфейса находится в:

```text
src/integrations/telegram/README.md
```

## Профиль пользователя

Пользовательские данные импортируются из YAML-шаблона.

Профиль содержит:

### 🏢 Данные работодателя

- company_name
- company_address
- service_agreement_date
- registration_number
- city

### 🏦 Банковские реквизиты

- account_holder
- bank_name
- account_number
- iban
- bic
- account_holder_email
- account_holder_address

### 💳 Платёжные настройки

- payment_number
- payment_code
- payment_description

### 💰 Настройки Invoice

- invoice_amount

После импорта данные сохраняются в базе данных и используются всеми документами системы.

## Пользователи и доступ

Finpipe поддерживает несколько ролей.

### Guest

Неавторизованный пользователь.

Доступны только:

- информация о проекте;
- команда Who Am I.

### User

Авторизованный пользователь.

Доступны:

- профиль;
- документы;
- Gmail-интеграция;
- работа с подписью.

### Owner

Владелец сервиса.

Дополнительно доступно:

- управление пользователями;
- административные функции.

## Безопасность

- Gmail refresh token хранится в зашифрованном виде.
- Электронная подпись хранится в зашифрованном виде.
- Пользовательские данные вынесены из ENV в SQLite.
- Все действия пользователей записываются в audit log.
- Чувствительные данные не должны попадать в логи приложения.

## Архитектура

Высокоуровневая схема:

```text
Telegram
    ↓
Handlers
    ↓
Services
    ↓
ORM
    ↓
SQLite

Gmail
    ↓
Services
    ↓
ORM
```

Основные технологии:

- Python 3.14
- SQLite
- SQLAlchemy ORM
- Telegram Bot API
- Gmail API
- Poetry
- Pytest

## Хранение данных

Используется SQLite.

В базе данных хранятся:

- пользователи;
- профили;
- банковские реквизиты;
- настройки Invoice;
- подписи;
- Gmail-аккаунты;
- audit log;
- системные состояния.

Данные переживают перезапуск приложения.

Каталог базы данных создаётся автоматически при старте.

Подробности:

```text
docs/storage.md
```

## Локальный запуск

### 1. Создать виртуальное окружение

```bash
python -m venv .venv
source .venv/bin/activate
```

### 2. Установить Poetry

```bash
pip install poetry==2.2.1
```

### 3. Установить зависимости

```bash
poetry install --no-interaction --no-ansi --no-cache
```

### 4. Установить git hooks

```bash
poetry run pre-commit install
```

## Запуск Telegram-бота
